# 射撃練度分析ツール MaCo - Marksmanship Coach

**MaCo**（マコ）は、市販の射撃練度分析デバイス（Mantis X10 等）と同時装着して使う、自作の IMU 計測・記録ツールです。正式には Marksmanship Coach — Personal Training & Coaching System と位置づけ、個人でのドライファイア訓練とコーチング（低下原因の記録・分析）の両方を支援することを目指しています。撃発前後の銃口の動きを生データとして記録し、市販デバイスが表示するスコア・診断ラベルと突き合わせることで、将来的に自作の採点ロジックを構築するためのデータ収集基盤として設計されています。

現段階では自作スコアの算出は行わず、**Mantis 側のスコア・診断結果を教師データとして蓄積するフェーズ**にあります。

---

## 背景・位置づけ

Mantis X10 のような製品は、内部の物理数値（角速度・加速度の生データ）や採点アルゴリズムを公開していません。表示されるのはスコアと診断ラベルのみです。

そこで MaCo を Mantis と同時装着し、

1. 同じ撃発に対して MaCo 側で生の IMU データ（角速度・加速度）を記録
2. その撃発に対して Mantis が出したスコア・診断ラベルを手入力で記録
3. 両者を紐付けたデータを蓄積

することで、生データとスコアの対応関係を後から分析し、自作の採点式を構築するための教師データを作る、という位置づけです。

---

## 構成

| コンポーネント | 役割 |
|---|---|
| **M5StickS3 ファームウェア**（`m5stick_firmware/`） | 内蔵 IMU（BMI270）から角速度・加速度を 100Hz で取得し、BLE で常時ストリーミング送信するのみ。検知・採点ロジックは持たない |
| **Web アプリ**（`webapp/index.html`） | Web Bluetooth で IMU データを受信し、波形表示・撃発検知・軌跡描画・スコア記録・進捗管理・CSV 出力をすべてブラウザ側で行う |

撃発検知・スコア計算・ロギングをすべて Web アプリ側に寄せているのは、常時のリアルタイム可視化と両立させるためと、パラメータ調整をファームウェア書き換えなしで即座に反映できるようにするためです。

---

## 主な機能

### 1. リアルタイム角速度波形
* BLE で受信した Gyro X/Y/Z を Chart.js でリアルタイム表示（3 秒ウィンドウ）。

### 2. 撃発検知（ドライファイア・ハンマー式想定）
* **反動ではなく微振動を検知**: 実弾の反動を前提とせず、ハンマー（ストライカー）落下時の微小な衝撃を検知対象とする。
* **差分値ベースの検知**: 合成加速度の絶対値ではなく、サンプル間の変化量（差分）を監視。閾値はスライダーで調整可能（デフォルト 0.15 G/サンプル）。
* **検知デバッグ波形を常時表示**: 加速度差分の実測値と現在の閾値ラインを常時表示し、ドライファイアを試しながら閾値を追い込める。
* **不応期**: 800ms（連続検知による誤カウントを防止）。

### 3. 手動記録（自動検知の救済措置）
自動検知が発火しなかった場合に備えた手動記録機能。撃発の信頼性を担保するため、以下のロジックで T0（撃発の瞬間）を可能な限り正確に推定する。

* Mantis 側の表示を見てから押すボタンのため、押下時刻は実際の撃発より遅れることを前提とする。
* ボタン押下時刻から一定範囲（デフォルト 1.5 秒、調整可）を遡り、加速度差分の最大ピークを探索。
* ピークが見つかればそれを T0 として採用（`manual-peak`：自動検知とほぼ同等の精度）。
* ピークが見つからない場合のみ、固定の反応時間補正値（デフォルト 0.4 秒）を引いた時刻を推定 T0 とする（`manual-fallback`：精度は劣る）。
* 履歴には検知方式（自動 / 手動ピーク特定 / 手動推定）をタグ表示し、自動検知と同一のリストで管理。

### 4. 軌跡記録・可視化（照準〜撃発〜フォロースルー）
* **常時ローリングバッファ**にIMUデータを保持し、撃発検知時に**撃発 4 秒前〜0.5 秒後**を自動的に切り出す。
* Gyro X/Y を単純積分した相対角度変化を、中心を基準とした 2D 平面上の軌跡として SVG 描画。
* 時間経過を色のグラデーションで表現（**青＝照準期 → 黄＝撃発直前 → X＝撃発の瞬間 → 赤＝撃発後のフォロースルー**）。Mantis X10 の DHOT 表示と同様の見せ方。
* **スコア低下要因の内訳（暫定）**: 照準期・引き金操作期・撃発直前 100ms・撃発後フォローの 4 区間でブレ量を比較したバー表示。正式な重み付けは未確定で、Mantis スコアとの相関分析を進めた上で見直す前提。

### 5. Mantis 評価の記録
* 各ショットに **Mantis スコア**（数値）と **低下原因（個癖）** を手入力する欄を用意。
* 低下原因はプルダウン（ガク引き・押し込み・突き上げ・指のかけすぎ・指のかかりが浅い・呼吸のタイミング・グリップの緩み等）＋「その他」選択時は自由記述。
* 自作スコアの算出式は現時点で未実装。まずは Mantis スコアと生データ（D 値・軌跡・区間内訳）を対応付けて記録することを優先している。

### 6. データ収集進捗パネル
* 目標サンプル数（100 件）と、スコア帯（90/80/70/60/50 点台に各 20 件）ごとの収集件数を常時表示。
* 通常のドライファイアではスコアが 84〜98 点台に偏りやすいため、意図的に崩したショットを混ぜて分布を広げる運用を想定。

### 7. 取り付け角度キャリブレーション（回転補正）
* マガジン下部等、必ずしも水平・垂直に固定できない場所に取り付けた場合の回転ズレを補正する機能。
* 銃口を真下に向けて静止させた状態でボタンを押すと、その時点の Accel X/Y に漏れ出た重力成分から取り付けの回転角を逆算し、以降の軌跡描画・区間別ブレ量計算にこの回転を打ち消す補正をかける。
* 常に同一のマガジン・同一の固定位置で運用する前提であれば、初回に一度キャリブレーションすれば以降は再実施不要。固定がズレたと感じた場合のみ再実施する。
* CSV 出力にも記録した基準姿勢・回転角をコメント行として含める。

### 8. HUD モード
* スマートグラスへのミラーリング表示を想定した、黒背景・高コントラストの全画面オーバーレイ。

### 9. CSV エクスポート / 共有
* ショット No・時刻・検知方式・Mantis スコア・低下原因・最大ブレ・D 値・軌跡座標（X/Y/t）・生波形（Gyro X/Y）を含めて出力。
* iOS の保存制約に対応するため Web Share API に対応（非対応環境ではクリップボードコピーにフォールバック）。

## ハードウェア構成

| 項目 | 内容 |
|---|---|
| センサーデバイス | M5StickS3（ESP32-S3、内蔵 IMU: BMI270） |
| 通信 | BLE Notify（Nordic UART 系 UUID を流用） |
| サンプリングレート | 100Hz |
| パケット形式 | 28 byte（`uint32 timestamp_ms` + `float×6`：Gyro X/Y/Z, Accel X/Y/Z、リトルエンディアン） |
| 想定装着位置 | マガジン下部（弾倉に固定）。画面下向き・接続端子が射手側を向く向きを想定。撃鉄・ストライカーに近いほど微振動を拾いやすい |
| 受信環境 | iPhone 等 + Web Bluetooth 対応ブラウザ（Bluefy 等） |

ファームウェアは生データの送信のみを行い、撃発検知・採点ロジックは一切持たない。これは常時のリアルタイム可視化と両立させるための設計判断であり、パラメータ調整の柔軟性（Web 側の JS を直すだけで即反映）を優先したもの。

マガジンに固定する運用のため、複数マガジンを使い回すと固定角度がその都度変わりうる。同一の 1 本のマガジンに固定して使うことを前提とし、取り付け角度のズレはキャリブレーション機能（後述）で補正する。

---

## ファームウェア書き込み時の注意

M5StickS3 の個体・環境によっては、通常の USB 接続だけでは書き込み時に `Device not configured` エラーが発生し、Arduino IDE・M5Burner のいずれでも書き込みが失敗することがある。この場合、以下の手順で手動でダウンロードモードに入れることで書き込みが成功する。

1. M5StickS3 の電源を一度切る。
2. Arduino IDE で書き込み（→ボタン）を実行し、「Connecting...」の表示を待つ。
3. 表示が出たタイミングで、本体前面のボタン（ボタン A）を押しながら電源ボタンでリセットをかけ、ボタン A を押したまま数秒待つ。
4. 接続成功のログ（Chip is ESP32-S3 等）が出れば書き込みが進行する。

USB ケーブルは、データ転送に対応したもの（USB 3.x 規格を明記したもの等）を使用すること。充電専用ケーブルでは USB デバイスとして認識されない、または認識されても通信が確立できない場合がある。

## 使い方 (Usage)

1. **ファームウェア書き込み**: `m5stick_firmware/m5stick_firmware.ino` を Arduino IDE で M5StickS3 に書き込む（M5Unified ライブラリが必要）。書き込みが `Device not configured` エラーで失敗する場合は「ファームウェア書き込み時の注意」を参照。
2. **装着**: M5StickS3 をマガジン下部に固定し（画面下向き・端子が射手側）、Mantis X10 等と同時装着する。
3. **Web アプリを開く**: `webapp/index.html` を Web Bluetooth 対応ブラウザ（iPhone なら Bluefy 推奨）で開く。
4. **BLE 接続**: 「BLE接続」ボタンを押し、`MaCo-S3` を選択。
5. **取り付け角度のキャリブレーション**: 銃口を真下に向けて静止させた状態で「基準姿勢を記録」ボタンを押す。以降、同じマガジンを使う限り再実施不要。
6. **閾値調整**: 「撃発検知デバッグ」パネルで加速度差分の波形を見ながら、ドライファイアを数回試し、閾値スライダーを調整する。
7. **記録**: 
   - 自動検知が発火すればショット履歴に自動追加。
   - 発火しなかった場合は、Mantis 側の表示を確認してから「今の撃発を手動記録」ボタンを押す。
8. **Mantis 評価の入力**: ショット履歴の各行で Mantis スコアと低下原因（プルダウン／自由記述）を入力する。
9. **軌跡確認**: 各行の「表示」ボタンで、その撃発の軌跡（照準〜撃発〜フォロースルー）とスコア低下要因の内訳を確認できる。
10. **進捗確認**: 「データ収集進捗」パネルでスコア帯ごとの収集件数を確認しながら、偏りがあれば意図的に崩したショットを増やす。
11. **CSV 出力**: 目標件数（100 件）に到達したら CSV エクスポートし、Mantis スコアと生データの相関分析・自作採点式の検討に進む。

## 設定パラメータ

| パラメータ | デフォルト | 内容 |
|---|---|---|
| 撃発検知の閾値 | 0.15 G/サンプル | 加速度差分がこの値を超えた瞬間を撃発（T0）とみなす |
| 手動記録：反応時間の探索範囲 | 1.5 秒 | 手動ボタン押下時刻からこの秒数分遡ってピークを探索 |
| 手動記録：ピーク未検出時の固定補正 | 0.4 秒 | ピークが見つからない場合、押下時刻からこの秒数を引いた時刻を推定 T0 とする |
| Dmin / Dmax | 2.0 / 40 | 直前 100ms のブレ量 D の暫定スケーリング基準（自作スコア未実装のため参考値） |
| 方向判定の閾値 | 8 dps | 積算 Gyro X/Y から診断ラベルを暫定判定する際の閾値 |
| 不応期 | 800ms | 撃発検知後、次の検知を無視する時間 |
| 軌跡切り出し範囲 | 撃発 4 秒前 〜 0.5 秒後 | 照準〜撃発〜フォロースルーの記録範囲 |
| キャリブレーション平均サンプル数 | 20 サンプル | 基準姿勢記録時、直近何サンプルを平均してノイズを低減するか |

## 未実装・今後の課題

### 自作スコア算出式
現時点では算出しない方針。Mantis スコアと生データ（D 値・区間別ブレ量・軌跡形状）のペアを 100 件程度蓄積した後、相関分析・重回帰分析等を行い、閾値やスコア式を決定する予定。

* **目標サンプル数**: 100 件（90/80/70/60/50 点台に各 20 件程度）。
* スコアが偏ると回帰分析の精度が落ちるため、意図的に崩したショットを含めてスコア分布を広げる必要がある。
* 4 区間（照準期／引き金操作期／撃発直前／撃発後）の重みを安定して推定するには、多重共線性・非線形性を考慮した分析が必要になる可能性がある。

### スコア低下要因の区間分け
現在の 4 区間（照準期：4 秒前〜1 秒前、引き金操作期：1 秒前〜0 秒、撃発直前：100ms、撃発後）の境界は仮の設定。実データが集まり次第、見直しが必要。

### スマートグラス連携
HUD モードは現状 iPhone 画面上の全画面オーバーレイのみ。スマートグラスへの実際のミラーリング表示は未検証。

### 検知安定性
撃発検知の閾値（微振動ベース）は銃種・取り付け位置によって最適値が大きく変わる可能性がある。エアガン等、反動・振動が極めて小さい銃種では、この方式自体が機能しない可能性がある。

### 姿勢補正の限界
現在のキャリブレーションは、取り付けの回転ズレ（Z 軸まわりの回転）のみを補正する 2D 補正であり、前後・横方向の傾きは補正しない。マガジンへの固定という運用上、この成分は小さいと想定しているが、想定より大きい傾きが生じる場合は 3 軸姿勢補正（クォータニオン等）の導入を検討する必要がある。
