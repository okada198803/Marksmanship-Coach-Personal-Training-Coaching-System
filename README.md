# 射撃練度分析ツール MaCo - Marksmanship Coach

**MaCo**（マコ）は、市販の射撃練度分析デバイス（参照デバイス）と同時装着して使う、自作の IMU 計測・記録ツールです。正式には Marksmanship Coach — Personal Training & Coaching System と位置づけ、個人でのドライファイア訓練とコーチング（低下原因の記録・分析）の両方を支援することを目指しています。撃発前後の銃口の動きを生データとして記録し、参照デバイスが表示するスコア・診断ラベルと突き合わせることで、将来的に自作の採点ロジックを構築するためのデータ収集基盤として設計されています。

現段階では自作スコアの算出は行わず、**参照デバイス側のスコア・診断結果を教師データとして蓄積するフェーズ**にあります。

---

## 背景・位置づけ

参照デバイスのような製品は、内部の物理数値（角速度・加速度の生データ）や採点アルゴリズムを公開していません。表示されるのはスコアと診断ラベルのみです。

そこで MaCo を参照デバイスと同時装着し、

1. 同じ撃発に対して MaCo 側で生の IMU データ（角速度・加速度）を記録
2. その撃発に対して参照デバイスが出したスコア・診断ラベルを手入力で記録
3. 両者を紐付けたデータを蓄積

することで、生データとスコアの対応関係を後から分析し、自作の採点式を構築するための教師データを作る、という位置づけです。

---

## 構成

| コンポーネント | 役割 |
|---|---|
| **M5StickS3 ファームウェア**（`m5stick_firmware/`） | 内蔵 IMU（BMI270）から角速度・加速度を 100Hz で取得し、BLE で常時ストリーミング送信するのみ。検知・採点ロジックは持たない |
| **Web アプリ**（`webapp/index.html`） | Web Bluetooth で IMU データを受信し、波形表示・撃発記録・軌跡描画・スコア記録・進捗管理・CSV 出力をすべてブラウザ側で行う |
| **軸確認ツール**（`webapp/axis_check.html`） | センサー取り付け後、銃口の動作方向とGyro X/Y/Zの対応関係を実機で確認するための診断アプリ |

撃発記録・スコア計算・ロギングをすべて Web アプリ側に寄せているのは、常時のリアルタイム可視化と両立させるためと、パラメータ調整をファームウェア書き換えなしで即座に反映できるようにするためです。

## 主な機能

### 1. リアルタイム角速度波形
* BLE で受信した Gyro X/Y/Z を Chart.js でリアルタイム表示（3 秒ウィンドウ）。

### 2. 撃発の確定：手動記録＋T0確認モーダル
実銃検証を通じて、加速度差分の閾値方式による自動検知は、ボタンを押していないタイミングでも誤発火することが多々あったため、**撃発の確定は必ずボタン押下経由のみ**に限定している。

* 「今の撃発を手動記録」ボタンは、参照デバイス側の表示を見てから押す想定のため、押下時刻は実際の撃発より遅れることを前提とする。
* ボタン押下後、直ちに確定はせず、**T0確認モーダル**を表示する。押下時刻から遡って直近5秒間の加速度差分波形を表示し、まず全体（粗い解像度）をタップして大まかな撃発位置を選び、その前後500msを拡大表示した2枚目のグラフでさらに正確な位置を微調整してから確定する。
* モーダルを開いた時点の初期選択位置（推奨T0）は、廃止前の自動検知と同じ判定基準（加速度差分が検知閾値を超えた点の中での最大ピーク）で自動算出する。閾値を超える点が見つからない場合のみ、単純な最大ピーク→それも無ければ固定の反応時間補正値（デフォルト 0.4 秒）を引いた時刻、の順にフォールバックする。ただしこれはあくまで初期値であり、確定は必ず目視・タップ確認を経る。
* 履歴には検知方式（`manual-peak`＝推奨位置をそのまま採用 / `manual-fallback`＝ピーク未検出のため推定 / `manual-adjusted`＝タップで修正）をタグ表示する。

### 3. 軌跡記録・可視化（照準〜撃発〜フォロースルー）
* **常時ローリングバッファ**にIMUデータを保持し、撃発確定時に**撃発 4 秒前〜0.5 秒後**を自動的に切り出す。
* Gyro X/Y/Z の3軸角速度から**クォータニオンで銃口の絶対姿勢を逐次追跡**し、基準姿勢からの水平方向（パン）・垂直方向（チルト）のズレ角を軌跡として SVG 描画する。単純な角速度の時間積分では、銃を傾けた（ロールさせた）だけで軌跡が左右にずれてしまう問題があったため、この方式に変更した。銃身軸まわりのひねり（ロール）成分は軌跡に混入させない。
* 全ショット共通の固定スケールで描画し、ショット間で見た目の大きさを比較できるようにしている。スケール（枠の半径に対応する角度）はキャリブレーション設定パネルのスライダーで調整可能（デフォルト 5°、値を小さくすると軌跡が拡大表示される）。
* 時間経過を色のグラデーションで表現（**青＝照準期 → 黄＝撃発直前 → X＝撃発の瞬間 → 赤＝撃発後のフォロースルー**）。参照デバイスの軌跡表示と同様の見せ方。
* 撃発を待たず、常に直近4秒分の照準の動きをリアルタイムに描画し続ける（常時ローリング表示）。撃発確定時は一定時間フリーズ表示し、その後自動的にリアルタイム表示に復帰する。
* **スコア低下要因の内訳（暫定）**: 照準期・引き金操作期・撃発直前 100ms・撃発後フォローの 4 区間でブレ量を比較したバー表示。正式な重み付けは未確定で、参照デバイスのスコアとの相関分析を進めた上で見直す前提。

### 4. 低下要因ヒント（参考情報）
撃発後フォロースルー期の収束パターン、撃発直前の軌跡の横ブレから、それぞれ「反動予期の可能性」「突き出しの可能性」をヒント表示する。いずれも統計的な傾向に基づく参考情報であり、誤検知率2〜3割程度と精度は高くない。断定的な判定ではない。

### 5. 参照デバイス評価の記録
* 各ショットに **参照デバイスのスコア**（数値）と **低下原因（個癖）** を手入力する欄を用意。
* 低下原因はプルダウン（ガク引き・押し込み・突き上げ・指のかけすぎ・指のかかりが浅い・呼吸のタイミング・グリップの緩み・引き金を引きながら握り込み・握り込みすぎ・突き出し・反動予期・トリガースラップ・掌底の押し付けすぎ・銃口上がり・フォロースルー不足等）＋「その他」選択時は自由記述。
* 自作スコアの算出式は現時点で未実装。まずは参照デバイスのスコアと生データ（D 値・軌跡・区間内訳）を対応付けて記録することを優先している。

### 6. データ収集進捗パネル
* 目標サンプル数（100 件）と、スコア帯（90/80/70/60/50 点台に各 20 件）ごとの収集件数を常時表示。
* 通常のドライファイアではスコアが偏りやすいため、意図的に崩したショットを混ぜて分布を広げる運用を想定。

### 7. ジャイロ静止バイアスキャリブレーション
* ジャイロのゼロ点オフセットにより、静止していても軌跡が一定方向にドリフトし続ける現象への対策。
* BLE接続後、銃に装着する前の静止状態で「静止バイアスを記録」ボタンを押すと、直近約1秒分のGyroX/Y/Zの平均値をバイアスとして記録する。以降、軌跡構築・D値・区間別ブレ量・各種ヒント判定など、角速度を使う全ての計算でこのバイアスを差し引く。

### 8. HUD モード
* スマートグラスへのミラーリング表示を想定した、黒背景・高コントラストの全画面オーバーレイ。

### 9. CSV エクスポート / 共有
* ショット No・時刻・検知方式・参照デバイスのスコア・低下原因・最大ブレ・D 値・低下要因ヒント判定・軌跡座標（X/Y/t）・生波形（Gyro X/Y/Z、Accel X/Y/Z の6軸フル）を含めて出力。
* iOS の保存制約に対応するため Web Share API に対応（非対応環境ではクリップボードコピーにフォールバック）。

## ハードウェア構成

| 項目 | 内容 |
|---|---|
| センサーデバイス | M5StickS3（ESP32-S3、内蔵 IMU: BMI270） |
| 通信 | BLE Notify（Nordic UART 系 UUID を流用） |
| サンプリングレート | 100Hz |
| パケット形式 | 28 byte（`uint32 timestamp_ms` + `float×6`：Gyro X/Y/Z, Accel X/Y/Z、リトルエンディアン） |
| 想定装着位置 | 銃口下のレール（参照デバイスの直下）。レールは銃身軸と平行、画面下向き、接続端子（USB/Grove）が射手側を向く向きで運用 |
| センサー軸の対応（実機確認済み） | GyroX＝銃身軸まわりのロール（ひねり）、GyroY＝上下（ピッチ）、GyroZ＝左右（ヨー） |
| 受信環境 | iPhone 等 + Web Bluetooth 対応ブラウザ（Bluefy 等） |

ファームウェアは生データの送信のみを行い、撃発判定・採点ロジックは一切持たない。これは常時のリアルタイム可視化と両立させるための設計判断であり、パラメータ調整の柔軟性（Web 側の JS を直すだけで即反映）を優先したもの。

複数のレール・取り付け位置を使い回すと、センサー軸と銃口方向の対応関係がその都度変わりうる。取り付け位置・向きを変更した場合は、`axis_check.html` で軸の対応関係を再確認することを推奨する。

## ファームウェア書き込み時の注意

M5StickS3 の個体・環境によっては、通常の USB 接続だけでは書き込み時に `Device not configured` エラーが発生し、Arduino IDE・M5Burner のいずれでも書き込みが失敗することがある。この場合、以下の対応で書き込みが成功する。

1. ボード設定を「ESP32S3 Dev Module」にする（「ESP32 Dev」等の無印ESP32設定では失敗する）。
2. `USB CDC On Boot`: Enabled、`Upload Mode`: USB-OTG CDC (TinyUSB)、`USB Mode`: USB-OTG (TinyUSB) に設定する。
3. それでも失敗する場合は手動ダウンロードモードに入る：電源を切る→書き込み開始→「Connecting...」表示時にボタンAを押しながら電源操作でリセット→ボタンAを押したまま数秒待つ。

USB ケーブルは、データ転送に対応したもの（USB 3.x 規格を明記したもの等）を使用すること。充電専用ケーブルでは USB デバイスとして認識されない、または認識されても通信が確立できない場合がある。

## 使い方 (Usage)

1. **ファームウェア書き込み**: `m5stick_firmware/m5stick_firmware.ino` を Arduino IDE で M5StickS3 に書き込む（M5Unified ライブラリが必要）。書き込みが `Device not configured` エラーで失敗する場合は「ファームウェア書き込み時の注意」を参照。
2. **装着**: M5StickS3 を銃口下のレールに固定し（画面下向き・端子が射手側）、参照デバイスと同時装着する。
3. **Web アプリを開く**: `webapp/index.html` を Web Bluetooth 対応ブラウザ（iPhone なら Bluefy 推奨）で開く。
4. **BLE 接続**: 「BLE接続」ボタンを押し、`MaCo-S3` を選択。
5. **静止バイアスキャリブレーション**: 銃に装着する前、置いた状態で「静止バイアスを記録」ボタンを押す。
6. **デバッグ波形の目安ライン調整**: 「撃発検知デバッグ」パネルで加速度差分の波形を見ながら、ドライファイアを数回試し、閾値スライダーを調整する（このラインは手動記録前に波形のピークを目視確認する際の目安として使う）。
7. **記録**: ドライファイア後、参照デバイス側の表示を確認してから「今の撃発を手動記録」ボタンを押す。T0確認モーダルで撃発位置をタップして選択・確定する。
8. **参照デバイス評価の入力**: ショット履歴の各行で参照デバイスのスコアと低下原因（プルダウン／自由記述）を入力する。
9. **軌跡確認**: 各行の「表示」ボタンで、その撃発の軌跡（照準〜撃発〜フォロースルー）とスコア低下要因の内訳を確認できる。
10. **進捗確認**: 「データ収集進捗」パネルでスコア帯ごとの収集件数を確認しながら、偏りがあれば意図的に崩したショットを増やす。
11. **CSV 出力**: 目標件数（100 件）に到達したら CSV エクスポートし、参照デバイスのスコアと生データの相関分析・自作採点式の検討に進む。

| T0確認モーダルの拡大表示範囲 | 前後500ms | 大まかな位置タップ後、正確な位置決めのために拡大表示する範囲 |
| 手動記録：ピーク未検出時の固定補正 | 0.4 秒 | ピークが見つからない場合、押下時刻からこの秒数を引いた時刻を推定 T0 とする |

| 軌跡表示の倍率 | 5°（枠の半径に対応する角度） | 値を小さくすると軌跡が拡大表示される。キャリブレーション設定パネルのスライダーで調整可能 |
| 静止バイアスキャリブレーション平均サンプル数 | 100 サンプル（約1秒） | 静止バイアス記録時、直近何サンプルを平均してノイズを低減するか |

## 未実装・今後の課題

### 自作スコア算出式
参照デバイスのスコアと生データ（D 値・区間別ブレ量・軌跡形状）を用いた相関分析・回帰分析を実施済み（詳細は別紙分析レポート参照）だが、データセットにより結果の再現性が低く、現時点で信頼できるスコア式は得られていない。次回データ収集時、確定した軸対応（GyroX＝ロール、GyroY＝上下、GyroZ＝左右）を前提に、GyroZ・AccelX/Y/Zも含めた再検証を行う予定。

* **目標サンプル数**: 100 件（90/80/70/60/50 点台に各 20 件程度）。
* スコアが偏ると回帰分析の精度が落ちるため、意図的に崩したショットを含めてスコア分布を広げる必要がある。
* T0推定精度（本当に撃発の瞬間を捉えられているか）が回帰結果に影響する可能性があり、T0確認モーダルでの目視確認を徹底する必要がある。

### スコア低下要因の区間分け
現在の 4 区間（照準期：4 秒前〜1 秒前、引き金操作期：1 秒前〜0 秒、撃発直前：100ms、撃発後）の境界は仮の設定。実データが集まり次第、見直しが必要。

### 低下要因判定の拡充
座標系確定を受けて、GyroZ・AccelX/Y/Zを使った低下要因判定案（反動予期・銃口上がり・突き出し・押し込み・ガク引き等、全14項目）を整理済みだが未実装。次回データ収集後、各特徴量と参照デバイスのスコア・低下原因の関係を検証し、精度が確認できたものから実装する。

### スマートグラス連携
HUD モードは現状 iPhone 画面上の全画面オーバーレイのみ。スマートグラスへの実際のミラーリング表示は未検証。

### 検知安定性
撃発判定の目安となる閾値（微振動ベース）は銃種・取り付け位置によって最適値が大きく変わる可能性がある。エアガン等、反動・振動が極めて小さい銃種では、この方式自体が機能しない可能性がある。

### 姿勢ドリフト補正
クォータニオンによる姿勢追跡・静止バイアス補正は実装済みだが、加速度計によるドリフト補正（相補フィルタ等）は未実装。長時間（撃発4秒前からの照準期全体）での姿勢ドリフトが問題になる場合、段階的に強化を検討する。
